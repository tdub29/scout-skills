# minto-pyramid-principle

This per-book hub routes a structuring task to one Minto framework plus its reference. Identify the user's cue, read the referenced file(s) in full, then apply that framework's process and output exactly.

Book provenance: **Barbara Minto, *The Minto Pyramid Principle: Logic in Writing, Thinking and Problem Solving* (Minto International, 2010)**. Load the matching `references/*.md` file when a specific framework is needed.

## When to use

Use this hub when the user is **structuring thinking for communication** â€” a memo, report, email, recommendation, consulting document, executive summary, or deck â€” and the problem is *architecture*, not prose. Signals: "what's my main point," "how should I order this," "this rambles," "make this answer-first," "is this grouping logical," "structure this proposal," "write the executive summary," "define the problem." The orientation is Minto's: structure the pyramid (and the introduction that leads into it) *before* writing sentences, so the reader receives major ideas before supporting detail.

## Guardrails

- **Structure, not prose.** This hub decides *what goes where and in what order*. Once the pyramid is sound, sentence-level work (rhythm, diction, voice) belongs to `prose-editing` â€” do not modify it.
- **Structure, not rhetoric.** Minto organizes ideas logically; she does not coach persuasion tactics. For ethos/pathos/logos, argument moves, or copy framing, hand off to `persuasion-copy` â€” do not modify it.
- **Structure, not slideware.** For slide narrative, chart selection, and visual encoding, hand off to `knaflic` / `data-viz` â€” do not modify them. (Minto's own presentation chapters cover reflecting the pyramid on the page; those siblings go further on visuals.)
- **Don't answer from router memory alone.** Load the selected reference file(s) first and follow their process, checks, and failure modes.
- **One question per document.** A pyramid answers exactly one reader question. If the user has two, relate them or split the document â€” see `references/minto-scqa-introduction.md`.

## Workflow

1. Identify the user's intent: building the whole document, fixing the order, structuring the introduction, validating a grouping, choosing argument form, or defining/structuring a problem.
2. Pick the closest row(s) in the routing table.
3. Read those `references/*.md` files completely.
4. Apply the framework's process and produce its output artifact (a pyramid sketch, an SCQA introduction, a corrected MECE grouping, an argument-form recommendation, or a problem-definition-to-introduction map).
5. Combine references only when the user asks for an end-to-end pass â€” typically problem-definition-structuring â†’ scqa-introduction â†’ pyramid-structure â†’ mece-grouping â†’ answer-first delivery.

## Common failure modes (hub-level)

- **Editing prose instead of structure** â€” polishing sentences when the real fix is the order of ideas; the reader's confusion almost always comes from structure, not style (Ch 3).
- **Router-only answer** â€” summarizing a framework without loading the reference's full process and checks.
- **No single governing thought** â€” producing a "list of N things" with no one idea at the top that summarizes them.
- **Skipping the introduction** â€” jumping to the key line without an SCQA, so background leaks into the body (Ch 3 caveats).
- **Crossing into a sibling's lane** â€” doing rhetoric, prose, or slide design here instead of handing off to `persuasion-copy` / `prose-editing` / `knaflic` / `data-viz`.
