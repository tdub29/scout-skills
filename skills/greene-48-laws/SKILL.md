# greene-48-laws

This hub collapses the five atomic Greene clusters into one router plus references. Route by user cue, read the referenced file(s) in full, and apply that cluster's framework â€” including its detection/counter-read and ethical guardrail.

Book provenance: **Robert Greene, *The 48 Laws of Power* (Viking, 1998)**. Load the matching `references/*.md` file when a specific cluster is needed.

## When to use

Use this hub when the user wants to **understand, name, or defend against power tactics** â€” diagnosing office politics, deciding whether something is manipulation or legitimate influence, recognizing a move someone is using on them, choosing a counter-move, or auditing how legible/exposed they are in an adversarial environment. The orientation is **manipulation literacy and discrimination**: each reference teaches how a tactic works precisely so the user can label it and tell ethical influence apart from manipulation.

## Guardrails

- **Purpose is literacy, not predation.** Each reference keeps its discrimination framing (how to *recognize* the move on you) and its counter-move and ethical-guardrail sections. Lead with those when the user's context is cooperative or trust-based.
- **Context test.** Greene's laws are instrumentally effective in **zero-sum, adversarial** contexts and **corrode** intimate relationships, high-trust teams, and long-term collaborations. Always check the context before "applying" anything.
- **Distinguish defense from offense.** Learning to recognize these moves is defensive and broadly advisable. Deploying them is offensive and requires a genuinely adversarial context and a proportionate-value / would-they-endorse-it check.
- Do **not** answer from router memory alone; load the selected reference file(s) first and follow their process and guardrail.
- **Sibling power hubs** (not part of this book, do not modify): `machiavelli-prince` for realpolitik risk reasoning, `sun-tzu-art-of-war` for competitive strategy. Cross-reference them; don't duplicate them.

## Workflow

1. Identify the user's intent â€” are they trying to **recognize/label a move used on them**, **defend** against it, **diagnose** a political situation, or (with a genuinely adversarial context) **deploy** a tactic?
2. Run the context test: zero-sum/adversarial vs. cooperative/trust-based. In cooperative contexts, foreground detection and the ethical guardrail rather than deployment.
3. Pick the closest row(s) in the routing table.
4. Read those `references/*.md` files completely.
5. Apply the cluster's framework, detection cues, counter-moves, and ethical guardrail. Name the specific Law(s) so the user can see exactly which move is in play.
6. Combine clusters only when the user asks for a multi-lens read (e.g., concealment + tactical execution for a contested negotiation).

## Common failure modes (hub-level)

- **Coaching predation** â€” applying offensive deployment in a cooperative context instead of leading with detection and counter-moves.
- **Skipping the context test** â€” treating a trust-based relationship as a power contest, which creates the adversarial reality it assumes.
- **Router-only answer** â€” summarizing the cluster without loading the reference's full framework and guardrail.
- **Dropping the discrimination framing** â€” naming the tactic without helping the user tell manipulation from ethical influence.
- **Retired atomic names** â€” the five per-cluster skill folders were collapsed into this hub; use `references/` only.
