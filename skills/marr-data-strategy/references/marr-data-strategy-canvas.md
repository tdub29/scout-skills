
# Marr: Data Strategy Canvas

## When to Use

Use after one or more data use cases have been scoped and the question becomes how they fit together as a data strategy.

## Do Not Use For

Broad data governance design alone, warehouse architecture, or dashboard backlog grooming.

## Framework

Marr recommends using a small, focused set of use cases as the frame for the first data strategy, then deriving cross-cutting requirements for data, governance, technology, skills, implementation, budget, and review cadence.

## How to Apply

1. Start with shortlisted use cases, not a generic capability wishlist.
2. Limit the first wave to a manageable number of major use cases and quick wins.
3. Extract shared data needs and sources.
4. Extract shared governance, compliance, privacy, and quality controls.
5. Extract shared technology and integration needs.
6. Extract skills needs and decide build, hire, upskill, or outsource.
7. Sequence quick wins and transformational initiatives together.
8. Define when the strategy will be revisited.

## Output Format

- Strategy thesis.
- Use-case portfolio with quick wins and transformational bets.
- Cross-cutting requirements for data, governance, technology, skills, implementation.
- Shared investment plan.
- Now/next/later roadmap.
- Review cadence and revision triggers.

## Common Failure Modes

- Creating a strategy detached from selected use cases.
- Picking too many initiatives.
- Funding each use case separately and missing shared capabilities.
- Treating governance as a separate afterthought.
- Choosing quick wins only and avoiding strategic value.
- Choosing transformational bets only and losing buy-in before results appear.
