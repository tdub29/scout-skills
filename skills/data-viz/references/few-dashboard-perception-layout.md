# Few Dashboard: Perception Layout

## When to use

Trigger when the dashboard has the right measures but the screen does not scan. Cues: "where should these KPIs go," "dashboard layout," "visual hierarchy," "can't see what's important," "too cluttered," or "make this dashboard glanceable."

## The framework

Few applies visual perception to dashboards so the screen works within human limits: short-term memory is small, attention is drawn by contrast, and grouping is perceived before deliberate reading. A good dashboard arranges information to match meaning and use.

### Layout rules

1. **Group by meaning and workflow.** Put related measures together so relationships are perceived, not hunted.

2. **Order by importance and scan path.** Prime screen positions should hold the most important signals and exceptions.

3. **Use visual hierarchy sparingly.** Size, weight, color, and position should guide attention to what matters now.

4. **Use consistency to reduce learning.** Repeated metrics should use repeated layouts, scales, and encodings.

5. **Use whitespace as structure.** Spacing and alignment can replace borders, boxes, and decoration.

## How to apply

1. **Identify priority signals.** What should the viewer notice in the first five seconds?

2. **Cluster related content.** Group by objective, process stage, geography, product line, or decision flow.

3. **Design the scan path.** Place high-priority status and exceptions first; place context and diagnostics nearby.

4. **Assign emphasis.** Use contrast only for status, exceptions, or active comparison. Muted information should recede.

5. **Return a layout repair plan.** Include grouping, order, screen regions, whitespace/border changes, and color/emphasis changes.

## Common failure modes

- **Boxing everything.** Boxes make every region compete. Use alignment and whitespace first.

- **Highlighting too many items.** If everything is bold, red, or large, nothing is prioritized.

- **Separating signal from context.** A KPI without target, trend, or threshold often forces interpretation elsewhere.

- **Using inconsistent scale or layout for peers.** Comparable metrics should be visually comparable.

- **Filling every pixel.** Dense dashboards can still breathe; empty space can improve speed and accuracy.
